# Tenchi framework audit — 2026-08-22 (v0.14.0, HEAD 7746992)

A follow-up deep audit of the framework, one development cycle after the
[2026-08-08 audit](AUDIT.md) (v0.12.0). It re-checks that audit's unresolved
findings at HEAD and hunts for new defects, with the same lens: (1) make it easy
for coding agents to **build** backend APIs, and (2) make it easy for agents to
**consume** them — plus, new this cycle, (3) does the verification/receipt
machinery actually stop an agent from faking "done".

Method: six parallel deep reviews (core HTTP boundary; operational/durability
surface; machine-consumption surface; **verification/receipt machinery**; CLI
and tooling; examples, docs, packaging), each reading source and tests and
reproducing suspected bugs by execution. **confirmed** = reproduced with running
code; **suspicion** = traced in code but not executed.

## Baseline

Everything the repo gates on is green at HEAD:

- root project: `ruff format --check` and `ruff check` clean, Pyright strict
  0 errors, **1196 tests passing** (up from 922 last cycle)
- `examples/taskboard`: 87 tests passing, Pyright clean, `tenchi doctor` clean
- `examples/fieldnotes`: 17 tests passing, Pyright clean, `tenchi doctor` clean
- fresh `tenchi new` app against **PyPI `tenchi==0.14.0`**: ruff/format/pyright/
  pytest/doctor clean, `tenchi check` 9/9 — the "CI-grade as generated" claim
  holds on both PyPI and HEAD, and all three docs tutorials
  (getting-started, build-a-feature, existing-project) run verbatim to a green
  `verify --base-ref --change-plan` receipt.

The findings below are therefore all things the existing gates do not see.

## Verdict in one paragraph

The last cycle's work landed: **every confirmed high-severity defect from the
v0.12.0 audit (H1–H7) is fixed and regression-tested**, along with the large
majority of the medium findings (retry/`Retry-After` clamping, `retry_on_statuses`,
payload-safe client errors, MCP `isError`, per-status OpenAPI code enums,
structured `operation_error` on every `--json` path, structured doctor errors,
stdout purity, the orphaned-subprocess fix, contract examples, idempotency-key
OpenAPI surfacing, job-message manifests). The framework's discipline is, if
anything, further ahead. **But the marquee new feature of this cycle — the
source-bound `verify` receipt and plan-bound test-execution evidence, the
machinery whose entire purpose is to make a coding agent's "done" independently
trustworthy — has a confirmed integrity hole: the pytest-execution receipt is
forgeable by project-owned code.** That is the one finding that undermines a
stated guarantee rather than a convenience, and it is the top priority. Around it
sits a familiar-shaped set of medium defects: a cluster of composition-time
checks the framework promises but still misses, a declared-error serialization
crash that violates the honesty rule, a client path-traversal encoding gap, two
redaction/exactness gaps on the operational surface, four `doctor` blind spots,
and CI/release/version-cycle drift. None is architectural.

## High-severity findings

### H1. Plan-bound pytest execution evidence is forgeable by project-owned code (confirmed)

**`src/tenchi/_pytest_evidence.py` (write at `pytest_sessionfinish`, L328-367;
env-var contract L14-17, 250-274); consumed by `_checks.py:235-261` and
`_verify_operations.py:986-991`.**

The plan-bound test-execution receipt — the evidence that
`tenchi verify --change-plan` uses to prove the planned test actually ran and
passed — is a plain JSON file whose path (`TENCHI_PYTEST_EVIDENCE_PATH`), target,
and expected source identity are handed to the child pytest process as
environment variables. There is no signing, nonce, or out-of-band channel: the
parent reads whatever content is at that path after the subprocess exits. Any
code that runs inside that pytest process — a `conftest.py`, a pytest plugin, an
imported module — can read those variables and write the receipt itself. Tenchi's
own plugin writes at `pytest_sessionfinish`, but an `atexit`-registered handler
runs *after* all pytest hooks, so it deterministically wins the last write.

**Reproduced end-to-end to a full green `verify: passed`:** scaffold an app,
generate a real change plan for a use case, mark the planned test
`@pytest.mark.skip` (so it never executes; suite still exits 0), and add a
`conftest.py` whose `atexit` handler writes a fabricated all-passed receipt to
`TENCHI_PYTEST_EVIDENCE_PATH`. Committing everything so the source reports clean,
`tenchi verify --base-ref HEAD~1 --change-plan plan.json` then reports
`[passed] change plan …`, `verify: passed` — with the planned test never run.
The intended defenses were verified working *in isolation* first: a wrapping
decorator alone correctly produced `test execution produced ambiguous lifecycle
reports`, and a plain `pytest_sessionfinish` forgery correctly *lost* to the
plugin's last-write ordering. Only the `atexit` write wins, and it defeats all of
them at once. The same mechanism is reachable via `PYTHONPATH`+`sitecustomize`,
`PYTEST_ADDOPTS -p …`, or any imported module, because the child inherits the
full `os.environ`.

This breaks the two central AGENTS.md guarantees for change-plan evidence — "the
callable collected by pytest must retain that definition's source identity;
wrapping decorators therefore fail closed" and "requires … successful setup,
call, and teardown for every invocation; skipped … targets fail". The whole
point of the receipt is to be trustworthy when the entity producing it is an
agent editing the same repo; here that entity can mint a passing receipt for
work it never did. The CLI and the coding-agent MCP `verify` tool share this path.

**Fix direction:** do not trust a filesystem receipt written by the child.
Authenticate execution out-of-band — stream evidence to the parent over an
inherited pipe FD and accept only records the plugin proves it authored (e.g.
HMAC with a per-run secret the parent generates and the plugin echoes), rejecting
any receipt content that fails the check. More fundamentally, in-process project
code sharing the interpreter is an inherent trust boundary; collecting the
identity/lifecycle facts in a parent-controlled collection pass, rather than
inside the test session the project can instrument, is the durable answer.

**What an adversarial agent still CANNOT fake (verified, and worth stating so the
fix stays scoped):** redirecting the recorded source/baseline via `GIT_DIR`/
`GIT_WORK_TREE`/`GIT_CONFIG_*` (stripped by `_git.py:git_environment`); escaping
the source digest via absolute/`..` paths or symlinks into file content
(`O_NOFOLLOW` + `lstat`/`fstat` re-checks); dodging the persistent-change recheck
(identity re-captured after every project-owned command, ~8×); injecting via ref
names or paths; weakening a gate silently (`_verification_policy` enforces the
stronger of current/historical and fails closed on malformed/removed policy);
passing an incompatible snapshot analyzed as "unknown" (`compatibility.py`
fails closed on both `breaking` and `unknown`, with correct directional
variance). The receipt-integrity model is strong everywhere except the one place
project-owned code runs in-process — which is exactly where H1 lives.

## Medium-severity findings

### Composition-time checks the framework promises but misses

AGENTS.md's first principle is "fail at composition time, not request time." The
fixed H1/H3 from last cycle were exactly this class; these are the ones that
remain.

- **Incompatible media-type / body-type pairings compose, then 500 or 422 on
  every request (confirmed).** `contract(response=Model,
  response_media_type="application/octet-stream")` and `…="text/plain"` both
  compose, then every request → framework 500 ("requires str or bytes");
  `contract(request=Model, request_media_type="application/octet-stream")` →
  422 on every well-formed request; `response=bytes` under default JSON media
  500s on non-UTF-8 bytes. All statically detectable at `create_app()`.
  (`server.py:897-916, 1238-1256`; no check in `contract()` /
  `_annotation_adapter`.) *Fix: require str-shaped types for `text/*`,
  bytes/str for other non-JSON media, reject bytes under JSON media, at
  composition.*
- **`validate_media_type` accepts non-text codecs as a charset;
  `charset=zip` composes and then 500s every request (confirmed).**
  `_media_types.py:56-67` only checks `lookup_codec(charset)`, which succeeds
  for `zip`/`base64`/`hex`/`rot13`/`quopri`. (Wire-side hostile charsets are
  correctly rejected as 415 — the gap is declaration-time only.) *Fix: verify
  text-ness at declaration, e.g. `"".encode(charset)`.*
- **HEAD contracts may declare a response body; GET/HEAD may declare a request
  body (confirmed, low wire impact).** `contract(method="HEAD",
  response=Model)` composes and serializes a body the server then discards
  (verified no keep-alive desync under uvicorn/h11 — unlike old H1);
  `contract(method="GET", request=Model)` composes and then 415s any GET
  without a body. Wasted work plus a contract/OpenAPI documenting a body the
  method can never carry. (`contracts.py:588-602`.)

### Honesty-rule violation on the error path

- **A declared `AppError` carrying a non-finite float or non-UTF-8 `bytes` in
  `details` crashes envelope rendering into a framework 500 and skips outcome
  observers (confirmed under real uvicorn).** `errors.py:125-143` renders
  details with `to_jsonable_python(details, fallback=str)`, which keeps
  `nan`/`inf` as-is and decodes bytes as strict UTF-8; the Starlette
  `JSONResponse` in `_app_error_response` (`server.py:1491-1505`) then renders
  with `allow_nan=False` and raises, escaping the `except AppError` handler. A
  use case raising a **declared** 409 with `details={"score": float("nan")}`
  yields `500 INTERNAL_SERVER_ERROR, x-tenchi-error-source: framework`, and
  because the exception propagates past `endpoint`, `_notify_observers` never
  runs (verified: observer list stayed empty). This directly contradicts
  `error_body`'s own docstring ("a declared error always renders as its declared
  status rather than crashing serialization into a 500") and the honesty rule's
  app/framework distinction. *Fix: render details in an inf/nan-safe mode (or
  reject at `AppError()` construction) and give `_app_error_response` a
  detail-dropping fallback; notify observers on this path.*

### Machine-consumption surface

- **Path parameter `.` / `..` produces on-the-wire path traversal (confirmed).**
  `client.py:946-969` (`_build_path`) checks rendered path values only for
  empty/unfilled and encodes with `quote(value, safe="")` — which encodes `/`
  but leaves dot-segments intact. On contract path `/t/{id}/x`, `id=".."` is
  transmitted as `raw_path=/x` (the `/t/{id}` segments vanish under
  normalization) and `id="."` as `/t/x`. A machine caller passing a derived or
  attacker-influenced id silently reaches an unintended endpoint. The client
  already defends `/`-injection; it forgets dot-segments. *Fix: reject a
  rendered path value equal to `.` or `..`, mirroring the empty-value guard.*
- **Boolean request headers serialize as `True`/`False`, not canonical
  `true`/`false` (confirmed).** `client.py:1388-1402` uses plain `str(value)`,
  asymmetric with the query path (emits `true`) and the response-header
  renderer (explicitly lowercases bools, `contracts.py:1393`). Tenchi→Tenchi
  survives only via Pydantic lax mode; a strict/non-Python server or an
  OpenAPI-generated client following `type: boolean` can misread `True`.
  *Fix: lowercase bools in `_render_request_header_value`.*

### Operational / durability surface

- **Store conformance suites certify adapters that expire records too early
  (confirmed).** `_idempotency_store_conformance.py:224-318` and
  `_rate_limit_store_conformance.py:75-113` assert expiry *at* the boundary
  (advance == ttl) but never survival *before* it. A wrapper store honoring only
  **half** of every requested `reservation_ttl`/`completed_ttl` passes
  `verify_idempotency_store`; a rate-limit store whose windows reset at half the
  requested duration (while reporting full-duration hints) passes
  `verify_rate_limit_store`. A certified-but-early-expiring idempotency adapter
  silently widens the duplicate-execution window and drops replays; an
  early-resetting limiter doubles effective throughput. This is the executable
  form of last cycle's "no too-early-expiry negatives" note. *Fix: add mid-TTL
  survival probes (advance ttl/2 → record/window must still be active) to all
  three expiration cases.*
- **`JobDispatcher.dispatch` leaks payload field values in exception text on
  consumer-side schema skew (confirmed).** `jobs.py:385-387` validates the
  message with `validate_json`, which on mismatch raises a bare
  `pydantic.ValidationError` whose `str()` embeds the offending field value
  (`input_value='SECRET-TOKEN-abc123'`). Queue adapters are told to classify
  this exception and dead-letter; one that logs `str(exc)` writes durable
  payload content — exactly the artifact that outlives a deploy — into logs.
  Contradicts the framework's own redaction stance (the CLI task path uses
  `exc.errors(include_input=False)`) and last cycle's resolution note claiming
  consumers can classify "without exposing the rejected payload." Same class in
  `TaskRunner.run(input_json=…)` and `execute(request_json=…)` from worker code.
  *Fix: raise a payload-safe typed error carrying `errors(include_input=False)`,
  or document that adapters must never log `str(exc)`.*

### CLI and tooling

- **Public `route_map()` (and every `load_*` loader) permanently mutates
  `sys.path` and `sys.modules` (confirmed).** `_openapi_operations.py:109-125`
  and the sibling `_*_operations.py` loaders leave the app root on `sys.path`
  and leak `app.*` into `sys.modules`. Harmless in the exiting CLI process, but
  `route_map()` is a documented library entrypoint; an embedding process gets
  corrupted import state, and a second app with the same module names resolves
  to the first. The MCP server compensates with `isolated_project_imports`; the
  public path does not. *Fix: wrap the public loaders in
  `isolated_project_imports` or snapshot/restore import state.*
- **`doctor` false negatives: feature `__init__.py` and stray top-level
  `app/*.py` escape every dependency rule (confirmed).**
  `doctor.py:578-622` returns `None` for `app/features/<f>/__init__.py` and any
  top-level `app/<x>.py`, so import findings never apply. A feature
  `__init__.py` importing `app.infra…`, and an `app/util.py` importing Starlette
  + infra, both leave `tenchi doctor` reporting "no problems found" while
  inverting dependency direction. *Fix: classify feature `__init__.py` under the
  feature; flag unrecognized top-level `app/*.py`.*
- **`doctor` treats server-composition modules as optional that
  `map`/`check`/`verify` hard-require (confirmed).** `doctor.py:41-48` requires
  6 files and omits `app/server/{tools,jobs,evaluations,tasks,preflight}.py`.
  Deleting `app/server/tools.py`: doctor clean (exit 0), but `map --json` exits
  1 and `check` fails the tools step. An agent that runs doctor first gets a
  false all-clear. *Fix: add the composition modules the other commands require,
  or emit a structured "missing required composition module" finding.*
- **`doctor` and `app_map` silently skip symlinked directories on Python 3.12
  (confirmed on 3.12.3).** They scan with `Path.rglob("*.py")`, which does not
  descend into symlinked dirs before 3.13. A symlinked feature dir with a
  dependency-direction violation is invisible to `doctor`, and since `verify`'s
  architecture stage runs the same scan, `verify` passes over it — while
  `_app_map.py:671` uses `iterdir()` and *does* list the symlink, so `map` can
  show a feature node whose files were never scanned. Also breaks the map
  determinism guarantee across interpreter versions. *Fix: walk with explicit,
  cycle-guarded symlink resolution instead of version-dependent `rglob`
  defaults.*

### CI, release, and version-cycle drift

- **`release.yml` omits `fieldnotes` entirely — the "re-runs all checks" claim
  is false (confirmed).** `.github/workflows/release.yml:33-64` has todos and
  taskboard legs only; fieldnotes' tests, pyright, doctor, and four snapshot
  checks (all gated in `ci.yml`) never run before the tag publishes.
  AGENTS.md:462-464 promises the tag workflow "re-runs all checks."
- **Version-cycle rule violated: `main` carries unreleased package changes while
  still stamped 0.14.0 (confirmed).** 0.14.0 released 2026-08-17; commit d582abc
  (2026-08-19) then landed agent protocol v11, change-plan schema v2, and
  `_pytest_evidence.py` under `[Unreleased]` with no bump. AGENTS.md:454-457
  requires bumping at the *start* of a cycle "so `main` never claims a version
  PyPI already owns." *Fix: bump `pyproject.toml` and `__init__.py` to 0.15.0.*
- **`release.yml` `workflow_dispatch` skips the tag/version check and publishes
  (confirmed by reading).** The version-match step is `if:
  github.ref_type == 'tag'`; a manual dispatch from a branch runs checks then
  `uv publish` with whatever version pyproject claims — currently 0.14.0 content
  that differs from the released 0.14.0. Only the `pypi` environment protection
  and PyPI's duplicate rejection stand in the way. *Fix: fail when
  `ref_type != 'tag'`, or run the version check unconditionally.*
- **The docs site is not CI-gated on pull requests (confirmed).**
  `docs.yml` runs `lint/typecheck/test/build` only on push to `main`; `ci.yml`
  has no docs job. A PR breaking `docs/` beyond what `tests/test_docs.py`
  catches is discovered only when the Pages deploy fails after merge.
- **A docs tutorial invents a starter capability (confirmed).**
  `build-a-feature.mdx:177-178` says "the generated starter can require one
  process-configured API key at the HTTP boundary." A fresh `tenchi new` app has
  no hooks and no API-key mechanism — that's `examples/todos`'s optional
  `TODOS_API_KEY` hook, which the scaffold deliberately omits. An agent copying
  the tutorial looks for a capability that isn't there. *Fix: reword to point at
  `examples/todos`, or add the hook to the scaffold.*

## Low-severity findings (condensed)

**HTTP boundary.** Passthrough responses may emit `Set-Cookie` (exempted at
`server.py:1064`) though it is reserved for declared success headers everywhere
else, and passthrough still mutates the presenter's `Response` in place
(`server.py:1016-1074`). `_handle_http_exception` forwards `exc.headers` without
the response-header safety funnel (`server.py:1535-1545`; latent — only safe
framework 404/405 reach it today). After deadline expiry, a declared `AppError`
from post-cancellation cleanup returns its app status rather than 504
(`server.py:1443-1446`; matches the letter of the "no late *success*" invariant —
recording so it stays deliberate).

**Still-open prior HTTP findings (re-confirmed at HEAD):** header aliases with a
literal underscore are silently respelled to hyphens (now at least consistent
with OpenAPI); reserved-header asymmetry (`ErrorDef` may declare
`Set-Cookie`/`Deprecation`/`Sunset`, success contracts may not); repeated
`x-request-id` — envelope uses first value, `RequestInfo.headers` keeps last;
an all-defaulted context factory is treated as zero-arg so lifespan state is
never passed; `application/json; charset=utf-16` passes the media check then
422s as UTF-8 (should be 415); observer latency runs outside `contract.timeout`;
`Page`/`page()` accept negative/inconsistent `total` and unchecked items-vs-limit.

**Operational.** `TaskGroup`/`TaskRunner`/`PreflightGroup` direct construction
bypasses the composition-time validation their jobs/evaluations siblings enforce
(`tasks.py:97-231`, `preflight.py:49-59`). A preflight check raising spurious
`CancelledError` aborts the whole gate unstructured and cancels siblings
(`preflight.py:206-207`; same shape suspected in `evaluations._run_case`). The
evaluation per-case deadline excludes case-input isolation/validation, and a
run-time input failure is mislabeled `EVALUATION_RESULT_INVALID`
(`evaluations.py:740-747`, suspicion). Conformance identity-isolation never
probes delimiter-injection collisions (`scope="a", key="b-c"` vs `scope="a-b",
key="c"`). Documentation still doesn't state the same-transaction idempotency
wiring makes `IDEMPOTENCY_IN_PROGRESS`/`Retry-After` effectively unreachable
(concurrent duplicates block on the row lock instead of the polite 409); and
use-case observers still report `succeeded` when job/task result validation then
fails and rolls back, with no `RequestOutcome` counterpart for worker alerting.

**Machine-consumption (still-open prior findings, re-confirmed).** `AppError`
raised from a remote envelope drops the envelope's `request_id`
(`client.py`; the envelope schema advertises it). `list_tools` auth failures
surface as JSON-RPC `INTERNAL_ERROR` — indistinguishable from a server bug and
inconsistent with `call_tool`'s `ToolError` (`mcp.py:327-336` vs `:499-500`).
OTel marks declared/expected app errors `StatusCode.ERROR`, inflating error-rate
dashboards (`opentelemetry.py:319-322`). `RetryPolicy` requires
`max_attempts >= 2`, so a one-shot deadline is inexpressible
(`retries.py:47-52`). OpenAPI `operationId` disambiguation is route-order-
dependent (two `list_items` → the second gets `list_items_2`; reordering swaps
ownership) — unstable for external client generators (`openapi.py:870-874`). No
`servers` block in generated OpenAPI (external agents can't learn where the API
lives); no client pagination iterator. `render_openapi_snapshot` still serializes
with default `allow_nan=True` (`snapshots.py:20`).

**CLI / scaffold.** `tenchi new` lacks `--json`/`--dry-run` and is
non-transactional (partial dir on mid-scaffold failure) while `make` is both
(`cli.py:427-1231`). Generated apps pin unversioned `tenchi` yet ship static,
format-locked snapshots — a `uv sync` after a 0.15.0 release can red a freshly
generated, untouched app (`scaffold.py`). Dead `todo_not_found` ErrorDef in the
scaffold (`scaffold.py:343`). No `CLAUDE.md` shim in generated apps (the repo
keeps one because some harnesses load by that name). AGENTS.md module list still
omits `responses.py`.

**Examples / docs / packaging.** `fieldnotes` replicates the
`OwnerScope("__health__")` synthetic-scope bypass last cycle flagged in
taskboard — now copied into a second teaching surface
(`fieldnotes/app/server/routes.py:21`, `taskboard/app/server/routes.py:24`).
`dependabot.yml` covers only root `uv` — missing `github-actions`, docs `bun`,
and the two example `uv` lockfiles. `taskboard` is invisible on every public
teaching surface (no README/AGENTS.md, no docs mention). Framework error codes
are still enumerated nowhere in docs (mitigated by per-operation OpenAPI enums).
Root CI's zero-SHA/unreachable base-ref edge on first push/force-push is still
present — and the *generated app's* CI template already solves it, so the repo's
own CI is behind its own scaffold. AGENTS.md drift: "both examples" (there are
three), the CI description omits fieldnotes and docs, the verification checklist
still lists raw pytest/pyright/doctor per example while CI runs
`tenchi verify --base-ref`, and getting-started's scaffold table omits
`app/server/routes.py` and `app/shared/errors.py`.

## Priorities

1. **Close the receipt-integrity hole (H1).** This is the only finding that
   defeats a stated guarantee rather than a convenience, and it lives in the
   feature this cycle was built around. Authenticate execution evidence
   out-of-band (pipe FD + per-run HMAC), or collect lifecycle identity in a
   parent-controlled pass rather than inside the project-instrumentable test
   session. Add the missing tests: a `conftest.py`/`atexit`/plugin cannot forge
   the receipt; the child environment neutralizes `PYTHONPATH`/`PYTEST_ADDOPTS`/
   `sitecustomize` influence; the whole-suite `run_check` evidence path resists
   forgery with exit code 0.
2. **Finish the composition-time promise.** Reject incompatible media-type/
   body-type pairings, non-text charsets, and body-declaring HEAD/GET at
   `contract()`/`create_app()` — the same class as the fixed H1/H3.
3. **Fix the honesty-path crash and the two redaction/exactness gaps.**
   inf/nan/bytes-safe declared-error rendering (H-medium above); payload-safe
   job/task/execute validation errors; mid-TTL survival probes in the
   conformance suites.
4. **Fix the client encoding gaps.** Reject `.`/`..` path parameters; canonical
   lowercase boolean headers.
5. **Close the `doctor` blind spots.** Feature `__init__.py` and top-level
   `app/*.py` classification; required composition modules; symlinked-dir
   traversal; isolate the public loaders' import state.
6. **Repair CI/release/version-cycle drift.** Bump to 0.15.0; add fieldnotes to
   `release.yml` and guard `workflow_dispatch`; gate docs on PRs; fix the
   `build-a-feature` API-key claim; pin `tenchi` in the scaffold; broaden
   dependabot; give the receipt renderers `allow_nan=False`.

## Strengths worth preserving

- **The v0.12.0 audit's high findings are genuinely closed**, with regression
  coverage, not silenced — the test count rose 922 → 1196 and the fixes hold
  under independent re-execution.
- **Receipt integrity is strong everywhere project code does not run in-process**:
  Git env-var isolation, symlink/path-escape resistance in the source digest,
  post-command identity rechecks, fail-closed policy comparison, and
  fail-closed compatibility analysis (both `breaking` and `unknown`) with
  correct directional variance — all verified adversarially.
